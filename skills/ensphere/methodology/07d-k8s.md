# Kubernetes Read-Only Appendix — Session 07

Use this appendix only for explicitly authorized clusters and namespaces. It
inherits [07-cloud.md](07-cloud.md).

## Binding Boundary

Collect resource metadata and non-secret specifications only. Never display
Secret data, ConfigMap values that may be sensitive, pod environment values,
service-account tokens, or workload files. Never use `exec`, `attach`, `cp`,
port-forward, proxy, impersonation, ephemeral containers, or any create/apply/
patch/delete/scale/rollout action.

## Preflight

Record expected cluster/server, context, namespaces, active identity, and
excluded resources. Verify context and allowed operations:

```bash
kubectl config current-context
kubectl cluster-info
kubectl auth can-i --list
```

Do not use `--as` or `--as-group`. Stop on context/identity mismatch or if the
credential is broader than the approved collection role without operator
acceptance.

## Coverage Inventory

### RBAC and identity

- Roles/ClusterRoles and bindings, wildcard verbs/resources, aggregation,
  privilege-escalation verbs, and bindings to high-privilege roles;
- service-account names, automount settings, projected-token audience/expiry
  metadata, and workload identity annotations;
- actual `kubectl auth can-i` results only for the active authorized identity.

Permission combinations are policy-analysis facts. Do not create a pod, exec,
bind a role, or read a Secret to prove them.

### Workload and pod security

- Pod Security Admission namespace labels and exemptions;
- security contexts: privileged, root/non-root, escalation, capabilities,
  seccomp/AppArmor/SELinux, read-only filesystem, host namespaces, hostPath,
  device access, and service-account binding;
- image tags/digests, pull policy, registry source, signing/admission metadata,
  resource limits, probes, and disruption budgets;
- dangerous plain environment-value presence may be recorded by key name only;
  never output values.

### Network and exposure

- Services/Ingress/Gateway/API objects, external addresses, NodePorts, TLS and
  authentication annotations;
- NetworkPolicy coverage and default-deny posture;
- control-plane/etcd endpoint configuration when exposed through authorized
  metadata, plus audit and encryption-at-rest configuration facts;
- service-mesh mTLS/authorization policy metadata.

Do not connect to workload ports or internal services from this appendix.

### Admission, secrets metadata, and resilience

- validating/mutating webhooks, Gatekeeper/Kyverno policies and enforcement
  mode, exemptions, failures, and audit findings;
- Secret names/types/age and mount/reference names only—never `.data` or
  `.stringData` values;
- external-secret/sealed-secret controller configuration metadata without
  fetching referenced values;
- audit logging, backup-controller configuration, encryption-provider metadata,
  node version/support status, and namespace/resource-quota coverage.

## Safe Collection Examples

Select output fields deliberately so evidence artifacts do not accidentally
contain values:

```bash
kubectl get namespaces -o json
kubectl get roles,rolebindings --all-namespaces -o json
kubectl get clusterroles,clusterrolebindings -o json
kubectl get networkpolicies --all-namespaces -o json
kubectl get services,ingresses --all-namespaces -o json
kubectl get validatingwebhookconfigurations,mutatingwebhookconfigurations -o json
```

Before storing broad JSON output, filter it to required metadata/spec fields and
redact identities or endpoints as required. Do not collect Pods/Deployments as
unfiltered JSON when environment values may be embedded; query selected safe
fields instead.

## Imported Leads and Report

Trivy/Kubescape/kube-bench or other results remain imported leads. Preserve
tool/version, cluster/namespace scope, rule, source severity, artifact, and
parse state. Corroborate with current non-secret resource configuration.

Report exact cluster/namespaces, active identity, authorized resource kinds,
RBAC and admission facts, unreviewed namespaces/resources, imported provenance,
and evidence citations. Pod-creation, secret-read, node-access, or escape chains
are risk scenarios only and must not be executed.
