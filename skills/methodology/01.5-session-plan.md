# Session 01.5: Plan

## Objective

Turn the recon stack profile and inventories into a plan: which sessions run,
which checklists each session loads, and what is blocked or missing. Every
decision cites recon evidence.

Inputs: `config.md`, `progress.md`, `01-recon/report.md`,
`01-recon/target-profile.yaml`.

## Step 2: Decide each session

For each session cite the inventory rows showing whether the surface exists,
name the planned assets, endpoints, roles, and inputs, list required inputs
and whether each is available, and choose a decision from the contract.

| Session | Runs when recon shows |
|---------|-----------------------|
| 02 Injection | User-controlled data reaches a query, command, template, path, XML or object decoder, LDAP or XPath filter, or response header. |
| 03 Authentication | Login, session, token, reset, MFA, OAuth, or API-key flows exist. |
| 04 Authorization | Multiple users, roles, or tenants; owned objects; privileged functions; RLS-protected tables. |
| 05 XSS | User content reaches an HTML, DOM, markdown, email, or PDF render context. |
| 06 SSRF | A server-side fetcher, webhook, importer, previewer, or renderer accepts a URL. |
| 07 Cloud and platform | Cloud, Kubernetes, IaC, Cloudflare, or Supabase configuration is in scope. |
| 08 API | REST, GraphQL, RPC, gRPC, WebSocket, SSE, or webhook surface exists. |
| 08.5 Abuse and cost | Always, unless the target is a library, CLI, or offline client with no server component. |
| 08.7 Chains and workflows | The environment is `sandbox`. Decide `run` provisionally here; after Session 08.5, re-decide from the candidate tables: `not_applicable` when no chain or workflow candidate exists, `blocked` with reason "requires sandbox" on staging or with no live target. |

`not_applicable` needs affirmative absence evidence. Missing credentials,
failed discovery, or no observed result never justify it; use `blocked` or
`uncertain` and name what is missing.

Coverage label `full` requires every input for the planned surface. Otherwise
choose `partial`, `blocked`, `source_only`, `client_only`, or `cloud_only`
and state the effect.

## Step 3: Tell the operator what is missing

List every missing prerequisite in one place: provider CLI logins, API tokens,
the Supabase JWT secret, approved burst counts for staging measurement, a
staging URL when the project has one. Test accounts, roles, a second tenant,
and owned objects come from the sandbox fixtures and are only missing when
there is no sandbox. Give the exact command or action for each. An
assessment-level blocker (contract, Blockers) stops here and asks; anything
else is recorded and the plan continues with what can proceed.
